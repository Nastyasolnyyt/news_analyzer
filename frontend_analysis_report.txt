1) Какие endpoint'ы ожидает фронт
- Базовый префикс API: /api/v1
- Реально описаны в frontend/src/api.ts:
  - POST /api/v1/auth/login
    body: { login, password }
  - GET /api/v1/posts
    query: page, page_size, search, order, sort
  - GET /api/v1/posts/:id
- Дополнительно frontend/src/views/EntityProfile.vue ожидает:
  - getEntityById(id) -> нужен endpoint вида GET /api/v1/entities/:id
  - фильтрацию новостей по entity_id через getPosts({ entity_id: id }) -> нужен GET /api/v1/posts?entity_id=:id
- Роуты фронта:
  - /
  - /search
  - /news/:id
  - /entity/:id
  - /reports

2) Какие поля нужны в списках и detail view

A. Dashboard (frontend/src/views/Dashboard.vue)
Фронт принимает либо плоский объект, либо item вида { post, analysis, risks, entities }.
Используемые поля:
- id или post.id
- title или post.title
- created_at или post.created_at
- source или post.source
- content или text
- риск:
  - analysis.risk_level
  - item.risk_type
  - item.risks[0].risk_type
- сущности:
  - item.entities или item.post.entities
  - поля сущности: id, text, type

B. Search (frontend/src/views/Search.vue)
Использует GET /posts.
Нужные поля:
- id / post.id
- title / post.title
- created_at / post.created_at
- source / post.source
- content или text
- analysis.risk_level

C. Reports (frontend/src/views/Reports.vue)
Использует GET /posts.
Нужные поля:
- id / post.id
- title / post.title
- source / post.source
- created_at / post.created_at
- analysis.tonality

D. News detail (frontend/src/views/NewsDetail.vue)
Использует GET /posts/:id.
Нужные поля:
- post.title или title
- post.source или source
- post.created_at или created_at
- post.content или post.text или content / text
- entities: [{ id, label|type, name|text }]

E. Entity profile (frontend/src/views/EntityProfile.vue)
Ожидает:
- entity.text
- entity.type
- entity.details:
  - jurisdiction
  - description
  - address
  - founded
И связанные новости:
- newsData.items
- у новости: id, title, content

3) Где есть рассинхрон с output_module / БД
- Фронт работает с /posts, а таблица в БД называется articles
- В БД есть articles.text, а фронт местами читает content || text
- Риск в БД хранится в risks(article_id, risk_type, confidence, created_at), но фронт часто ищет analysis.risk_level
- В post_analysis нет поля risk_level; там есть emotion, tonality, relevance, confidence, sentiment_label, topic_id
- В БД сущности: named_entities(name, entity_type), а фронт ожидает text, type
- Во view EntityProfile.vue ожидается details, которых нет в реальной БД
- frontend/src/views/EntityProfile.vue вызывает api.getEntityById, но такого метода нет в frontend/src/api.ts
- EntityProfile.vue вызывает api.getPosts({ entity_id: id }), но текущая сигнатура getPosts(page = 1, pageSize = 20, search = '') этого не поддерживает
- frontend/src/components/SearchWorkspace.vue содержит моковые данные, но основной Search.vue уже работает с реальным API
- Во фронте есть fallback-логика:
  - item.post || item
  - data.items || data
  - post.content || post.text
  - analysis.risk_level || 'low'

Response, совместимый с фронтом:

  "id": 10,

D. Для связанных новостей сущности:
GET /api/v1/posts?entity_id=10
Response shape тот же, что и у списка

Особо важные точки:
- Самый совместимый контракт для фронта: { items, total }, где каждый item содержит post, analysis, risks, entities
- Для фронта критично поле created_at
- Для текста достаточно text, потому что фронт делает content || text
- Для риска лучше вернуть risks и дополнительно продублировать значение как analysis.risk_level
- Для сущностей нужны alias-поля:
  - text
  - type

Отдельный внутренний рассинхрон фронта:
- frontend/src/views/EntityProfile.vue использует методы API, которых нет в frontend/src/api.ts
- ожидание details у entity не соответствует реальной схеме named_entities
